# ProstojMenu

Единая оболочка игрового меню Prostoj для uMod/Oxide. Команда игрока — `/menu`; обновлённый `ProstojRUST` также открывает свою вкладку через `/store`.

## Установка

1. Развернуть `api/controllers/v1/RustMenuController.php`, маршрут из `api/config/web.php` и выполнить миграции `m260817_120000_optimize_rust_menu_support_queries` и `m260817_121000_optimize_rust_menu_public_sections`.
2. Установить `ProstojMenu.cs`, затем обновлённый `ProstojRUST.cs` в `oxide/plugins`.
3. В `oxide/config/ProstojMenu.json` указать:
   - `API URL`: `https://api.prostoj.store/v1/rust-menu/snapshot`;
   - `Battle Pass API URL`: `https://api.prostoj.store/v1/rust-menu/battlepass`;
   - `Support API URL`: `https://api.prostoj.store/v1/rust-menu/support`;
   - `Rust server secret`: тот же `secret_key`, который хранится у сервера в liscase;
   - `Server tag`: уникальный `servers.tag` (рекомендуется вместо IP/порта).
4. Проверить `/menu`, все семь вкладок, Battle Pass, отправку и получение ответа в «Поддержке», а также выдачу тестовой покупки через `/store`.

## Battle Pass в игре

Встроенная вкладка `BATTLE PASS` повторяет страницу `/battlepass`: использует тот же сезон, медаль, прогресс игрока, основной путь, VIP-задания и изображения наград. Задания выводятся ограниченными страницами по шесть карточек, а при первом открытии лента сразу фокусируется на текущем этапе. Текущую доступную карточку можно нажать: проверка, атомарная выдача награды и открытие следующего этапа выполняются тем же кодом, что на сайте.

Battle Pass загружается отдельным запросом только при открытии вкладки и не увеличивает общий snapshot меню. Контракт формируется тем же `BattlePassController`, что и сайт, поэтому статусы, прогресс и награды не расходятся между веб-интерфейсом и игрой.

- `GET /v1/rust-menu/battlepass` — активный сезон и персональный прогресс;
- `POST /v1/rust-menu/battlepass/tasks/{id}/check` — проверить текущий этап и выдать награду;
- заголовок `X-Rust-Server-Secret`, `steam_id` и данные текущего сервера обязательны;
- ответ персональный и всегда отправляется с `Cache-Control: private, no-store`.

## Поддержка в игре

Вкладка «Поддержка» работает с теми же обращениями, что сайт: сообщение игрока создаёт или продолжает обычный тикет `support`, сразу появляется у сотрудников, а их ответ автоматически подгружается в открытый игровой диалог. Пока вкладка открыта, новые ответы проверяются с разнесённым интервалом 13–19 секунд; также доступно ручное обновление. Игрок идентифицируется по Steam ID, запрос подписывается секретом текущего Rust-сервера. Для незарегистрированного пользователя показывается ссылка на вход через Steam.

Готовый макет вкладки для Rust CUI Editor: `plugins/ProstojMenu_Support_UI.json`.

Игровой API:

- `GET /v1/rust-menu/support` — история обращений и сообщения выбранного тикета;
- `POST /v1/rust-menu/support/messages` — создать обращение или отправить сообщение;
- заголовок `X-Rust-Server-Secret`, query-параметры `steam_id` и `server_tag` обязательны так же, как для snapshot API.

### Архитектура производительности

- Любая коллекция в основном ответе имеет жёсткую границу: 8 обращений, 12 сообщений, 8 категорий по 3 лидера и максимум 100 строк для счётчиков непрочитанного. Сезонная лента загружается отдельно и рисует только 6 заданий на одной странице.
- `support` читается по покрывающему индексу `(user_id, status, updated_at, id)`, а непрочитанные — по `(user_id, status, id, support_id)`. История сообщений использует существующий InnoDB-индекс `support_id`, внутри которого уже хранится первичный `id`.
- Топ игроков использует тот же готовый кэш `StatsCacheHelper`, что и `/stats/{server}`: восемь категорий по три лидера. Rust Menu лишь нормализует и кэширует ограниченный payload на 60 секунд; отдельных запросов рейтинга для каждого открывшего меню игрока нет.
- Общие для всех игроков данные календаря, топа и списка кланов кэшируются отдельными маленькими payload на 60 секунд. Персональные баланс, статистика, клан и поддержка не смешиваются с публичным кэшем.
- Календарь выполняет две индексные выборки (события сервера и глобальные обновления), затем объединяет максимум 128 строк в памяти. Кланы сначала выбирают восемь лидеров по опыту, после чего число активных участников считается одной пакетной выборкой только для этих кланов.
- Полный ответ содержит `revision`. Фоновый запрос передаёт её как `known_revision`; если ничего не изменилось, API возвращает `unchanged: true` без загрузки сообщений, пользователей и read-receipts.
- Счётчики являются точными до отображаемого предела. Значение 100 означает «100 и более», что исключает полный `COUNT(*)` по многолетней истории.
- Записи для получателей создаются одним `batchInsert`; список сотрудников кэшируется на 60 секунд. Read-receipts загружаются пакетно и ограничены 250 последними ID, при этом все подходящие записи всё равно помечаются прочитанными.
- Плагин запрещает параллельные запросы одного игрока, не перерисовывает CUI при неизменном тихом ответе и распределяет polling по времени, чтобы сотни игроков не создавали один синхронный всплеск.

Персональные ответы имеют `Cache-Control: private, no-store`. Кэшировать их на CDN нельзя; горизонтальное масштабирование API выполняется обычными stateless PHP-репликами с общими Redis, БД и очередью уведомлений.

В конфиге также доступны URL фонового арта и базовый URL изображений сайта. В карточке статистики используется персональный Steam-аватар из API, а не общий декоративный персонаж:

- `Background image URL`: `https://prostoj.store/images/rust-menu/prostoj-command-center-v2.jpg`;
- `Images base URL`: `https://prostoj.store/images` — база для логотипа, иконок наград и ресурсов.

### Локальный кэш изображений

Все внешние изображения проходят через единый кэш `ProstojMenu`: логотип, фон, монета баланса, награды, ресурсы, Steam-аватары, аватары сообщений поддержки, картинки товаров и иконка корзины `ProstojRUST`. Клиент Rust больше не получает прямые URL сайта.

1. При первом появлении URL сервер скачивает изображение с сайта, преобразует его в PNG и атомарно сохраняет в `oxide/data/ProstojMenu/Images/`.
2. PNG регистрируется в Rust `FileStorage`, а CUI получает только локальный `Png` ID.
3. После перезагрузки плагина файл читается из `oxide/data`; HTTP-запрос не выполняется.
4. Повреждённый локальный PNG удаляется точечно и заново скачивается. Одновременно выполняется не более трёх загрузок, одинаковый URL никогда не ставится в очередь дважды.

Имя файла содержит SHA-256 от полного URL, поэтому разные хосты, query-параметры и аватары не конфликтуют. Встроенные игровые спрайты Rust, например иконка закрытия `assets/icons/close.png`, уже являются локальными ресурсами клиента и в этот каталог не копируются.

Секрет передаётся в заголовке `X-Rust-Server-Secret`, а не в URL. Query-параметр `secret` оставлен на API только для обратной совместимости.

## Подключение другого плагина

В подключаемом плагине:

```csharp
[PluginReference] private Plugin ProstojMenu;

private void OnServerInitialized()
{
    ProstojMenu?.Call("API_RegisterTab", this, "quests", "ЗАДАНИЯ", "TASK", 60);
}

private void Unload()
{
    ProstojMenu?.Call("API_UnregisterTab", this, "quests");
}

private object ProstojMenu_Render(BasePlayer player, string parent, int page)
{
    // Добавить CUI-элементы внутрь parent. Имена элементов должны быть
    // уникальны для плагина; оболочка удалит их при следующей перерисовке.
    return true;
}
```

Доступные вызовы оболочки:

- `API_RegisterTab(owner, key, title, icon, order)` — зарегистрировать или заменить вкладку. Для встроенных CUI-пиктограмм используйте `SHOP/STORE`, `PASS/SEASON/TASK`, `WIPE/CALENDAR`, `STAT/CHART`, `TOP/RANK` или `CLAN/TEAM`; неизвестное значение получает нейтральную иконку модуля;
- `API_UnregisterTab(owner, key)` — удалить вкладку и вернуть встроенную, если она была заменена;
- `API_Open(player, tab)` / `API_Close(player)` — открыть или закрыть меню;
- `API_IsTabActive(player, tab)` — проверить, открыта ли вкладка;
- `API_RefreshTab(player)` — перерисовать активное содержимое;
- `API_ShowToast(player, message, kind)` — уведомление (`info`, `success`, `error`);
- `API_CacheImage(url)` — поставить внешний ресурс подключаемого модуля в общую очередь локального кэша;
- `API_GetImage(url)` — получить `FileStorage` PNG ID; возвращает `null`, пока первая загрузка не завершилась.

Встроенные ключи: `store`, `battlepass`, `calendar`, `stats`, `top`, `clans`, `support`. Подключаемый плагин может заменить встроенную вкладку тем же ключом; после его выгрузки стандартная вкладка восстанавливается автоматически.

## Макет

`ProstojMenu_UI.json` — статический макет вкладки календаря для Rust CUI Editor: месячная сетка, события, легенда, единый фон и sidebar. `ProstojMenu_Stats_UI.json` — отдельный макет статистики с персонажем, наградами и ресурсами. Они нужны для визуальной проверки и не загружаются игровым плагином во время работы.

В календаре команды `prostojmenu.ui calendar_prev` и `prostojmenu.ui calendar_next` переключают месяцы. Сетка и цветовые категории повторяют календарь на странице сервера: глобальный вайп — оранжевый, обновление — синий, вайп карты — зелёный, текущая дата — красная рамка.
