# Решения для статических файлов из frontend/web/uploads

## ❌ Минусы символической ссылки в public/uploads:

1. **Медленная разработка**
   - Next.js сканирует все файлы в `public` при запуске
   - Hot reload может быть очень медленным с большим количеством файлов
   - Увеличение времени сборки

2. **Большой размер проекта**
   - Все файлы считаются частью проекта
   - Проблемы с Git (если не в .gitignore)
   - Медленный деплой (нужно копировать все файлы)

3. **Проблемы с деплоем**
   - На Vercel/Netlify нужно копировать все файлы
   - Увеличение времени деплоя
   - Ограничения по размеру

## ✅ Рекомендуемые решения:

### Вариант 1: Использовать CDN (УЖЕ ЕСТЬ В НАСТРОЙКАХ) ⭐ ЛУЧШИЙ

У вас уже есть `site_cdnUrl` в настройках базы данных. Используйте его:

```typescript
// В formatImageUrl уже реализовано
const cdnUrl = settings.site_cdnUrl; // Например: https://cdn.prostoj.store
const imageUrl = formatImageUrl('/drop/123.png', cdnUrl);
// Результат: https://cdn.prostoj.store/uploads/drop/123.png
```

**Плюсы:**
- ✅ Файлы не в проекте
- ✅ Быстрая разработка
- ✅ Быстрый деплой
- ✅ Кэширование на CDN
- ✅ Уже реализовано для продуктов

### Вариант 2: Next.js Rewrites (для локальной разработки)

Настроить проксирование через Next.js rewrites:

```javascript
// next.config.js
async rewrites() {
  return [
    {
      source: '/uploads/:path*',
      destination: 'http://localhost/uploads/:path*', // или URL старого фронтенда
    },
  ];
}
```

**Плюсы:**
- ✅ Файлы не в проекте
- ✅ Работает в development
- ✅ Можно использовать локально

**Минусы:**
- ❌ Не работает в production (нужен доступ к старому серверу)
- ❌ Дополнительная нагрузка на сервер

### Вариант 3: Nginx/Apache проксирование (для production)

Настроить веб-сервер для проксирования:

```nginx
# nginx.conf
location /uploads/ {
    alias /path/to/frontend/web/uploads/;
    expires 30d;
    add_header Cache-Control "public, immutable";
}
```

**Плюсы:**
- ✅ Файлы не в проекте
- ✅ Быстрая отдача статики
- ✅ Кэширование

### Вариант 4: Символическая ссылка (только если другие варианты не подходят)

Если все-таки нужна символическая ссылка:

```powershell
# От имени администратора
cd C:\xampp\htdocs\liscase\frontend-new\public
mklink /D uploads "C:\xampp\htdocs\liscase\frontend\web\uploads"
```

**Когда использовать:**
- Только для локальной разработки
- Если нет доступа к CDN
- Если нужна полная автономность

## 🎯 Рекомендация:

**Используйте CDN (Вариант 1)** - это уже реализовано и работает для продуктов. Просто убедитесь, что `site_cdnUrl` правильно настроен в базе данных.

Для локальной разработки можно добавить fallback на rewrites, если CDN недоступен.
