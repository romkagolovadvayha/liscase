# Тест-кейсы для API партнерской программы

## 1. GET /v1/user/partner/conditions - Условия программы

### TC-PARTNER-API-001: Успешное получение условий программы
- **URL**: `GET /v1/user/partner/conditions`
- **Авторизация**: Требуется (JWT token в заголовке Authorization)
- **Действие**: Отправить GET запрос на endpoint
- **Ожидаемый результат**: 
  - Статус код: 200
  - Структура ответа:
    ```json
    {
      "success": true,
      "data": {
        "description": "Условия партнерской программы"
      }
    }
    ```
- **Проверки**:
  - ✅ Поле `success` равно `true`
  - ✅ Поле `data` присутствует
  - ✅ Поле `data.description` присутствует и является строкой

### TC-PARTNER-API-002: Получение условий без авторизации
- **URL**: `GET /v1/user/partner/conditions`
- **Авторизация**: Отсутствует
- **Действие**: Отправить GET запрос без токена
- **Ожидаемый результат**: 
  - Статус код: 401
  - Сообщение об ошибке авторизации

### TC-PARTNER-API-003: Проверка структуры ответа условий программы
- **URL**: `GET /v1/user/partner/conditions`
- **Авторизация**: Требуется
- **Действие**: Проверить структуру JSON ответа
- **Ожидаемый результат**:
  - Все обязательные поля присутствуют
  - Типы данных соответствуют спецификации

## 2. GET /v1/user/partner/invite - Как приглашать?

### TC-PARTNER-API-004: Успешное получение информации о приглашении
- **URL**: `GET /v1/user/partner/invite`
- **Авторизация**: Требуется (JWT token в заголовке Authorization)
- **Действие**: Отправить GET запрос на endpoint
- **Ожидаемый результат**: 
  - Статус код: 200
  - Структура ответа:
    ```json
    {
      "success": true,
      "data": {
        "ref_code": "12345",
        "referral_link": "http://example.com/p/12345",
        "partnerLink": "http://example.com/p/12345",
        "referral_percent": 5.0,
        "referral_clicks": 10,
        "registered_count": 5,
        "played_count": 3,
        "referral_balance": 1000.50
      }
    }
    ```
- **Проверки**:
  - ✅ Поле `success` равно `true`
  - ✅ Поле `data` присутствует
  - ✅ Поле `data.ref_code` присутствует (может быть пустой строкой)
  - ✅ Поле `data.referral_link` присутствует (может быть пустой строкой)
  - ✅ Поле `data.partnerLink` присутствует (дубликат referral_link для совместимости)
  - ✅ Поле `data.referral_percent` присутствует и является числом (float)
  - ✅ Поле `data.referral_clicks` присутствует и является числом (int, >= 0)
  - ✅ Поле `data.registered_count` присутствует и является числом (int, >= 0)
  - ✅ Поле `data.played_count` присутствует и является числом (int, >= 0)
  - ✅ Поле `data.referral_balance` присутствует и является числом (float, >= 0)

### TC-PARTNER-API-005: Получение информации о приглашении без авторизации
- **URL**: `GET /v1/user/partner/invite`
- **Авторизация**: Отсутствует
- **Действие**: Отправить GET запрос без токена
- **Ожидаемый результат**: 
  - Статус код: 401
  - Сообщение об ошибке авторизации

### TC-PARTNER-API-006: Проверка корректности данных статистики
- **URL**: `GET /v1/user/partner/invite`
- **Авторизация**: Требуется
- **Действие**: Проверить, что все числовые значения корректны
- **Ожидаемый результат**:
  - `referral_percent` >= 0
  - `referral_clicks` >= 0
  - `registered_count` >= 0
  - `played_count` >= 0
  - `referral_balance` >= 0
  - `played_count` <= `registered_count`

### TC-PARTNER-API-007: Проверка формирования партнерской ссылки
- **URL**: `GET /v1/user/partner/invite`
- **Авторизация**: Требуется
- **Действие**: Проверить формат партнерской ссылки
- **Ожидаемый результат**:
  - Если `ref_code` не пустой, то `referral_link` должен содержать `/p/{ref_code}`
  - Если `ref_code` пустой, то `referral_link` должен быть пустой строкой
  - `partnerLink` должен быть равен `referral_link`

## 3. GET /v1/user/partner/referrals - Мои рефералы

### TC-PARTNER-API-008: Успешное получение списка рефералов
- **URL**: `GET /v1/user/partner/referrals`
- **Авторизация**: Требуется (JWT token в заголовке Authorization)
- **Действие**: Отправить GET запрос на endpoint
- **Ожидаемый результат**: 
  - Статус код: 200
  - Структура ответа:
    ```json
    {
      "success": true,
      "data": {
        "referrals": [
          {
            "id": 1,
            "userId": 1,
            "username": "test_user",
            "steam_id": "76561198000000000",
            "avatar": "https://example.com/avatar.jpg",
            "created_at": "2024-01-01 00:00:00",
            "hasBonus": false,
            "hasSkinSent": false,
            "hasHourInServer": true,
            "canGetReward": true
          }
        ],
        "total": 1
      }
    }
    ```
- **Проверки**:
  - ✅ Поле `success` равно `true`
  - ✅ Поле `data` присутствует
  - ✅ Поле `data.referrals` присутствует и является массивом
  - ✅ Поле `data.total` присутствует и является числом (int, >= 0)
  - ✅ `data.total` равен длине массива `data.referrals`

### TC-PARTNER-API-009: Получение списка рефералов без авторизации
- **URL**: `GET /v1/user/partner/referrals`
- **Авторизация**: Отсутствует
- **Действие**: Отправить GET запрос без токена
- **Ожидаемый результат**: 
  - Статус код: 401
  - Сообщение об ошибке авторизации

### TC-PARTNER-API-010: Структура элемента списка рефералов
- **URL**: `GET /v1/user/partner/referrals`
- **Авторизация**: Требуется
- **Действие**: Проверить структуру каждого элемента в массиве referrals
- **Ожидаемый результат**:
  - ✅ Каждый элемент имеет поле `id` (int)
  - ✅ Каждый элемент имеет поле `userId` (int), равное `id`
  - ✅ Каждый элемент имеет поле `username` (string)
  - ✅ Каждый элемент имеет поле `steam_id` (string)
  - ✅ Каждый элемент имеет поле `avatar` (string, может быть пустой)
  - ✅ Каждый элемент имеет поле `created_at` (string, дата)
  - ✅ Каждый элемент имеет поле `hasBonus` (boolean)
  - ✅ Каждый элемент имеет поле `hasSkinSent` (boolean)
  - ✅ Каждый элемент имеет поле `hasHourInServer` (boolean)
  - ✅ Каждый элемент имеет поле `canGetReward` (boolean)

### TC-PARTNER-API-011: Пустой список рефералов
- **URL**: `GET /v1/user/partner/referrals`
- **Авторизация**: Требуется (пользователь без рефералов)
- **Действие**: Получить список рефералов для пользователя без рефералов
- **Ожидаемый результат**:
  - Статус код: 200
  - `data.referrals` является пустым массивом `[]`
  - `data.total` равен 0

### TC-PARTNER-API-012: Логика canGetReward
- **URL**: `GET /v1/user/partner/referrals`
- **Авторизация**: Требуется
- **Действие**: Проверить логику поля `canGetReward`
- **Ожидаемый результат**:
  - `canGetReward` = true, если `hasHourInServer` = true и НЕ (`hasBonus` = true И `hasSkinSent` = true)
  - `canGetReward` = false, если `hasHourInServer` = false или (`hasBonus` = true И `hasSkinSent` = true)

### TC-PARTNER-API-013: Лимит на количество рефералов
- **URL**: `GET /v1/user/partner/referrals`
- **Авторизация**: Требуется (пользователь с большим количеством рефералов)
- **Действие**: Получить список рефералов
- **Ожидаемый результат**:
  - Максимум 100 рефералов в списке (лимит задан в коде)
  - Рефералы отсортированы по `created_at` в порядке убывания (DESC)

## 4. Интеграционные тесты

### TC-PARTNER-API-014: Переключение между вкладками вызывает разные API
- **Frontend**: Компонент ProfileReferralClient
- **Действие**: 
  1. Открыть вкладку "Условия программы"
  2. Открыть вкладку "Как приглашать?"
  3. Открыть вкладку "Мои рефералы"
- **Ожидаемый результат**:
  - ✅ При открытии "Условия программы" вызывается `GET /v1/user/partner/conditions` и `GET /v1/user/partner/invite`
  - ✅ При открытии "Как приглашать?" вызывается `GET /v1/user/partner/invite` и `GET /v1/user/partner/promocode`
  - ✅ При открытии "Мои рефералы" вызывается `GET /v1/user/partner/referrals`

### TC-PARTNER-API-015: Обработка ошибок API
- **URL**: Все три endpoint
- **Авторизация**: Требуется
- **Действие**: Симуляция ошибки сервера (500) или сетевой ошибки
- **Ожидаемый результат**:
  - ✅ Frontend корректно обрабатывает ошибку
  - ✅ Показывается понятное сообщение об ошибке пользователю
  - ✅ Не происходит краша приложения

### TC-PARTNER-API-016: Обработка состояний загрузки
- **Frontend**: Компонент ProfileReferralClient
- **Действие**: Переключение между вкладками
- **Ожидаемый результат**:
  - ✅ Во время загрузки показывается скелетон (skeleton loader)
  - ✅ После загрузки данные отображаются корректно
  - ✅ При ошибке показывается сообщение об ошибке

## 5. Тесты производительности

### TC-PARTNER-API-017: Время ответа API
- **URL**: Все три endpoint
- **Авторизация**: Требуется
- **Действие**: Измерить время ответа
- **Ожидаемый результат**:
  - ✅ Время ответа < 1 секунды для всех endpoint'ов
  - ✅ Для `/user/partner/referrals` время ответа < 2 секунд даже при большом количестве рефералов

- **Frontend**: Компонент ProfileReferralClient
- **Действие**: Переключение между вкладками несколько раз
- **Ожидаемый результат**:
  - ✅ Данные кэшируются (если используется React Query или аналоги)
  - ✅ Не происходит дублирования запросов при быстром переключении
